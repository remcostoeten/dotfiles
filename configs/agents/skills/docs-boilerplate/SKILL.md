# docs-boilerplate

A documentation site starter. Pages are MDX files in `content/docs`, the sidebar is built from folders and `meta.json` files, and the site is configured in one object, `src/shared/config/site.ts`. The stack is Next.js 16 with Cache Components, React 19, Tailwind 4, Fumadocs 16, AI SDK 7 and TypeScript 6, run with Bun. Lint and format use Oxlint and oxfmt through Vite+ (`vp`). There is no ESLint or Prettier.

## Before you change anything

1. Read `AGENTS.md` in the project root. It holds the commands, layout and the rules that fail a build.
2. Run `git status` and leave unrelated changes alone.
3. Next.js here is newer than most training data. Read the matching guide in `node_modules/next/dist/docs/` before touching routes, caching or `next.config.ts`.
4. Read the project's own docs for the feature: `content/docs/**` is the source of truth, and the running site serves every page as Markdown at its URL plus `.mdx`.

## Rules that apply everywhere

- Never hardcode the site name, site URL or repository URL. They come from `site` in `src/shared/config/site.ts` and `getRepository()` in `src/shared/config/repository.ts`.
- Never put a secret in a committed file. Keys go in `.env.local`, which is gitignored, and in the host environment. Ask AI keys are read from the environment only.
- A new page is a file in `content/docs` plus an entry in the `pages` array of the `meta.json` in its folder. A page missing from `pages` builds but is not in the sidebar.
- Never edit `.source`, `.next` or a generated changelog page. A generated page starts with the `generated by scripts/sync-changelog.ts` marker.
- Do not export `dynamic`, `revalidate` or `fetchCache` from a route. They fail the build with Cache Components on.
- Standalone functions are `function` declarations and callbacks are arrow functions. Do not add comments, ESLint or Prettier.
- Prose in docs is plain and specific. No em dashes and no marketing language.

## Verify

Run these one at a time, not in parallel, and fix what they report:

```bash
bun run check      # format check and lint
bun run typecheck  # regenerates .source and route types, then tsc
bun test
bun run build      # changelog sync, internal link check, then next build
```

`bun run build` is the one that catches broken internal links, unknown frontmatter fields and type errors in `twoslash` code blocks. Run it after moving pages, changing frontmatter or touching `source.config.ts`. Say which checks you ran and which you skipped.
