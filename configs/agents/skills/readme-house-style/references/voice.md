# Voice

Applies to every section.

Plain declaratives about what the software does. The reader is a developer deciding
whether to spend five minutes on this, and confident specifics are what earn that.

Never use em dashes. A comma, a full stop, or a rewrite handles every case one would
have covered.

Do not write the marketing scaffolding that AI-written READMEs default to: no "Why
this is fast", "Why this matters", "Key benefits", "Built with love", no emoji
section headings, no exclamation marks, no "blazing" unless the project already used
the word about itself, no closing invitation to contribute or star the repo.

Claims must be checkable in the repo. If a number or a benchmark appears, it comes
from a file in the repo, and the README links to it.

Placeholders in the templates are ALL CAPS. None may survive into the output. If a
placeholder cannot be filled truthfully, drop the line it is on, or the section, per
the profile.
