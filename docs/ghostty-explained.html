The loop that makes it feel live: the TUI writes configs/ghostty/config in the repo → the symlink means that is ~/.config/ghostty/config → SIGUSR2 tells the running process to re-read it → your open windows repaint. Editing the file by hand and running pkill -USR2 -x ghostty yourself does the identical thing.

Hypothetical: one file → three

Ghostty has a real include directive: config-file. Paths are relative to the file doing the including, so a repo-local split needs no absolute paths. Everything here is composed into one flat key/value list before anything is applied — includes are not scoped.

Fragments
font.conf
Family, size, cell metrics. Nothing else knows about it.
theme.conf
Palette, opacity, blur, background image. The part ghostty-theme would own.
keybinds.conf
All 20 keybind = lines. Additive, so order against the others doesn't matter.
Entry point
config
Shrinks to three config-file lines plus whatever you want to override afterwards.
the only name ghostty looks for
order matters
Includes are expanded in place. A font-size written after the include beats the one inside it — last write wins for scalar keys.
Result
one flat config
Identical to today's single file. Ghostty can't tell the difference — and neither can ghostty-theme, which is exactly the catch.
Why the repo doesn't do this today: ghostty-theme parses and rewrites one file (configs/ghostty/config) with a line-by-line replace. Split the file and the TUI would rewrite font-size into the entry point while font.conf still holds the old value — two sources of truth for one key. A split needs the tool taught which fragment owns which key first.

How Ghostty gets inside your shell

You never sourced anything. The terminal arranges for fish to find its integration script on its own, then removes its own fingerprints so child shells don't inherit them.

1 · Before exec
set the environment
TERM=xterm-ghostty, TERM_PROGRAM, GHOSTTY_RESOURCES_DIR, GHOSTTY_SHELL_FEATURES.
prepend XDG_DATA_DIRS
Adds /usr/share/ghostty/shell-integration to the front of the search path.
2 · fish starts
scan vendor_conf.d
fish sources <dir>/fish/vendor_conf.d/*.fish for every entry in XDG_DATA_DIRS. Ghostty's dir is now one of them.
ghostty-shell-integration.fish
Runs, installs prompt/preexec hooks, then un-prepends XDG_DATA_DIRS so a nested shell isn't double-hooked.
3 · What you get
OSC 133 marks
Prompt boundaries → jump between prompts, select a command's whole output.
cwd reporting
Feeds window-inherit-working-directory. New splits open where you were.
cursor + title
Bar cursor while typing, block in normal mode; title tracks the running command.
Check it yourself: env | grep GHOSTTY inside a Ghostty window. You'll see GHOSTTY_SHELL_FEATURES=cursor:blink,path,title — those three words are literally the feature switches, settable from the config with shell-integration-features.
